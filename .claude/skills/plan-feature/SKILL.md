# Skill: plan-feature

## Purpose
Plan a change from verified repository evidence without turning planning into an automatic stopping point.

## Procedure
1. Read `AGENTS.md`, relevant scoped rules, code, package/build configuration, and architecture docs.
2. Restate the requested outcome as observable acceptance criteria.
3. Identify affected files, dependencies, generated outputs, deployment boundaries, and regression risks.
4. Choose the smallest coherent implementation slices and the closest verifier for each slice.
5. Record a durable plan only when the work is long-running or the user explicitly needs one.
6. If implementation was requested and no approval gate or blocker exists, continue into implementation in the current client.
